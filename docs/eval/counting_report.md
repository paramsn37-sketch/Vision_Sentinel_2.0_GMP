# Counting evaluation (MOT17)

Generated by `backend/eval/counting_eval.py`. Data: the second half of each MOT17 training sequence (boxmot
`MOT17-50` release). Ground truth = distinct pedestrian IDs (class 1, `consider` = 1). Predicted tracks that
spend most of their life on distractors (static people, cyclists, reflections) are not counted.
Detector: **yolo26n-coco (fallback, person only)** at 640 px. Thresholds tuned on MOT17-02/04 (216 trials),
reported on sequences never used for tuning.

## Shipped defaults (note added after this run)

The shipped `config/default.yaml` uses the chosen thresholds above with one product constraint:
`min_hit_ratio` is **0.5** (not 0.3) so that a box that flickers for 2 frames out of 10 is never counted
(unit test `test_flicker_detections_never_counted`). Measured with the same cached detections:
mean unique-count error on the reporting sequences **20.0 %** (0.5) vs **19.7 %** (0.3).
`counting_eval.py` now applies this constraint itself, so the next run reports it directly.
